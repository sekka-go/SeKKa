# سِكّة | SeKKa

تطبيق رحلات مشتركة يومية وباقات أسبوعية وشهرية بواجهة عربية RTL. النسخة المنشورة تستخدم Supabase Edge Function لواجهات API؛ مجلد Express/SQLite القديم باقٍ كبيئة تطوير محلية منفصلة ولا يمثل قاعدة بيانات الإنتاج.

## التقنية والتصميم

- الواجهة: React 19 وTypeScript وVite وPWA. واجهة RTL عربية مع ترجمة إنجليزية وثيمين فاتح وداكن.
- مدير الحزم: pnpm 11.19.0. الخلفية المنشورة: Supabase Postgres وEdge Function باسم `sekka-api`؛ خادم Express/SQLite نموذج محلي قديم للاختبار وليس قاعدة الإنتاج.
- الخط: Tajawal. لوحة الألوان الحالية: أصفر SeKKa `#F5BD08`، فحمي/كحلي `#172033`، خلفية فاتحة `#F1F5F9`، أسطح بيضاء، تركواز `#087B80` في الوضع الفاتح و`#53C6C5` في الداكن. حافظ على تباين النص وحالات النجاح والتحذير والخطأ عند تعديل الألوان.
- الواجهة تستعمل Leaflet لاختيار المواقع وعرض المسارات. هندسة الطريق تُطلب من Supabase Edge Function عبر OSRM؛ الخدمة العامة المتاحة افتراضيًا تجريبية وبأفضل جهد. مصدر بلاطات الخريطة الإنتاجي الحالي هو `tile.openstreetmap.org`، وهذا يخالف هدف المستودع بتقديم بلاطات عبر PMTiles/R2. إعداد PMTiles/R2 غير موجود، لذلك يلزم إعداد المصدر البديل قبل إصدار يغيّر تكامل الخرائط.

## تشغيل وفحص محلي

يتطلب Node.js 22 أو أحدث. من جذر المستودع:

```powershell
pnpm install
```

إعدادات البيئة الاختيارية موضحة في [`.env.example`](.env.example). لا تحتاج إلى ملف `.env` لتشغيل الإعداد المحلي الافتراضي. إذا أضفت إعدادًا، استخدم مفتاح Supabase العام فقط في متغيرات `VITE_*`، وضع مفاتيح الخدمة ورموز المزودين في إعدادات Supabase السرية فقط.

في نافذتين منفصلتين:

```powershell
# الخادم المحلي القديم، على 127.0.0.1:3001
pnpm --filter sekka-server dev
```

```powershell
# واجهة Vite، على 127.0.0.1:5173
pnpm dev
```

افتح `http://127.0.0.1:5173/`. Vite يمرر `/api` إلى خادم SQLite المحلي. أوامر التحقق:

```powershell
pnpm lint
pnpm typecheck
pnpm test
pnpm build
deno test supabase/functions/sekka-api
```

اختبارات `pnpm test` تغطي خادم SQLite القديم؛ واختبارات Deno تغطي وظائف مساعدة في Edge Function. نجاحها لا يثبت مطابقة قاعدة الإنتاج أو تدفقًا كاملًا في المتصفح. لاختبارات SQL المحلية يلزم تشغيل Supabase المحلي وDocker.

## النموذج المحلي القديم

التعديلات والنشر الحاليان يمران عبر فرع GitHub وCloudflare Pages وSupabase المحددين للمشروع. التعليمات التالية تخص نموذج Express/SQLite القديم للتطوير فقط، ولا تعكس إعدادات النسخة المنشورة.

يُنشئ الخادم قاعدة البيانات تلقائيًا في `server/data/sekka.db`. لا تضع بيانات إنتاج أو أسرار في قاعدة SQLite المحلية.

## إصدار GitHub وSupabase وCloudflare

1. أنشئ فرعًا وPR إلى `main` في `sekka-go/SeKKa`؛ لا تتجاوز مراجعة GitHub أو فحوص CI. يتضمن المستودع فحوص الواجهة والخادم، ولا يحتوي على سير عمل نشر Cloudflare في GitHub Actions.
2. قبل تعديل قاعدة Supabase، تحقّق من معرّف المشروع المرتبط، ثم راجع `supabase migration list --linked` وقارن كل migration محلي بالتاريخ البعيد. راجع SQL واختبارات pgTAP أولًا. لا تستخدم `db push` قبل التأكد من أن التغييرات الإضافية متوافقة مع بيانات الإنتاج والنسخة المنشورة. انشر Edge Function `sekka-api` بعد توافق مخطط قاعدة البيانات معها، واحفظ الأسرار في إعدادات Supabase فقط.
3. إعداد Cloudflare Pages موجود خارج المستودع. في لوحة Pages تحقّق من المستودع والفرع الذي ينشر الإنتاج، أمر البناء `pnpm build` ومجلد الناتج `web/dist`، ثم راقب نتيجة النشر. لا توجد في هذا المستودع هوية مشروع Wrangler أو إعداد موثق للنشر اليدوي؛ لا تخمّن اسم المشروع. إذا استُخدم Wrangler، استخدم اسم مشروع Pages القائم بعد التحقق منه وسجّل الدخول عبر Wrangler دون إدخال الرموز في الملفات.
4. بعد النشر افحص رابط الإنتاج، سجلات النشر، واجهة التطبيق، طلبات API، والخريطة. نشر GitHub وحده لا يثبت تحديث Supabase أو Cloudflare.

متغيرات الواجهة: `VITE_API_BASE_URL` (اختياري لتجاوز عنوان API) و`VITE_SUPABASE_PUBLISHABLE_KEY` (مفتاح عام فقط). متغيرات Edge Function المضبوطة عبر Supabase تشمل بحسب الميزة `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SEKKA_ROUTING_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET`, `SEKKA_ALLOWED_ORIGINS` ومفاتيح VAPID. لا تطبع أو تضع أي قيمة سرية في Git أو حزمة المتصفح.

## إعداد التوجيه والخرائط

- واجهة الويب تدعم التثبيت كتطبيق PWA؛ تفاصيل التثبيت والعمل دون اتصال في [دليل PWA](docs/pwa.md).

- يستخدم مسار الإنتاج الحالي بلاطات OpenStreetMap العامة عبر Leaflet وبنسبة بيانات ظاهرة؛ اختيار الموقع يتم بالنقر فقط ولا يوجد بحث نصي. راجع ملاحظة مزود البلاطات أعلاه قبل إطلاق جديد.
- يحسب Supabase Edge Function الطريق الفعلي عبر خدمة OSRM في `SEKKA_ROUTING_URL`، والإعداد الحالي الافتراضي هو `https://router.project-osrm.org`. يرسل الخادم إحداثيات محطات الرحلة إلى مزود التوجيه العام عند حساب الطريق.
- خدمة OSRM العامة تجريبية وبأفضل جهد بلا ضمان توافر. إذا تعذر حساب الطريق، تعرض الواجهة رسالة خطأ ولا تستبدله بخط مستقيم. بلاطات OSM لا تُحفظ أو تُحمّل مسبقًا للعمل دون اتصال.
- إعدادات OSRM المحلية في خادم Express القديم منفصلة عن إعداد Supabase Edge Function ولا تُستخدم في النسخة المنشورة.

## الفلو المتاح

- تسجيل الراكب أو الكابتن وتسجيل الدخول وإدارة كلمة المرور.
- الراكب يحدد المواقع على الخريطة، الفئة، أيام الخدمة والمواعيد؛ ويستطيع إنشاء مجموعة ومشاركتها ومتابعة الركاب والرحلات والإشعارات.
- الكابتن يكمل ملف المركبة والتحقق التطويري للهاتف، يحدّث موقعه وقدراته، يقبل المسارات ويتابع نقاط الركوب والنزول.
- الإدارة تراجع توثيق الكباتن وتتابع مؤشرات التشغيل.
- تعرض لوحة الإدارة حالة مجموعات Pool والقيود الدفترية المستحقة للشركة والكباتن، من دون صلاحية تحصيل أو تحويل.
- Faster: مقاعد 3، والحد الأدنى راكبان. Saver: مقاعد 4، والحد الأدنى 3 ركاب. الباقة الأسبوعية 5 أيام بخصم 5%، والشهرية 22 يومًا بخصم 10%.
- الدفع الفعلي وبوابة الدفع وتسوية العمولة مؤجلة. تحتفظ المنظومة بالمبالغ والاستردادات المستحقة كبيانات تشغيلية فقط.
- إشعار عدم اكتمال الحد الأدنى يُعالج بعد 72 ساعة، ويتيح الانتظار أو حجز المقاعد المتبقية أو الإلغاء المجاني.
- إعدادات السيارة ونطاق بحث الكابتن محفوظة وتُستعاد عند تسجيل الدخول. تحدّث الرحلات والإشعارات تلقائيًا أثناء الاستخدام.

تفاصيل جميع المسارات والحقول والردود في [توثيق API للمرحلة 11](docs/pool-phase-11-api.md).

## حساب الإدارة المحلي

قاعدة البيانات الجديدة تهيئ حساب إدارة تطويريًا موضحًا في migrations. استخدم بيانات الدخول المحلية للتطوير فقط وغيّر كلمة المرور مباشرة بعد أول تسجيل دخول؛ لا تستخدم الحساب الافتراضي في الإنتاج.
