## Scope and evidence rules

`docs/CONTROL_INVENTORY.json` was regenerated with the existing AST-based `web/scripts/audit-controls.cjs`: **504 JSX control declarations** across 24 TSX modules (including developer-gallery and preview controls). Each raw entry records file, line, element, handler/URL/change prop, disabled expression, and available accessible label. It is a source index, not proof that each action works.

The table below records production-facing high-risk flows and visible navigation controls. An `onClick` is not counted as success: backend completion requires a successful response and, where applicable, a verified owned row. “Preserves data” distinguishes browser session state from durable Supabase persistence. No real Staging write was made. Unlisted gallery-only controls are not production actions; they remain indexed in the JSON file.

## Silent/dead-end and misleading-success findings

- **Confirmed guest dead end:** S014 request creation is shown without a signed-in identity; see P2-01.
- **Unavailable feature is explicit:** favorites callback errors rather than pretending to save; the flow is still missing.
- **No fabricated booking success:** the live reservation flow verifies an owned persisted row and reports pending, not paid/confirmed.
- **No role escalation in UI:** Admin entry depends on `v31_is_admin`; the synthetic test proves metadata alone is ignored, but real RLS is not validated.
- **No duplicate global bottom nav on onboarding/search:** CI layout tests cover selected guest views.
- Controls in `/dev/screens` that manipulate fixture balances, approvals, routes, or mock ledgers are not real actions and must never be cited as acceptance.
