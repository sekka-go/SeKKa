## Verified architectural blockers

1. `web/src/main.tsx` serves `MobileApp` on public paths; `SubscriptionApp` renders the approved screens only under `/dev/screens`.
2. `web/src/v2/api.ts` throws `V31_DOMAIN_BACKEND_NOT_READY` for all legacy `api(operation)` calls; do **not** remove this safety guard or reconnect obsolete RPCs.
3. `Discovery.tsx` contains preview examples. Production must never display these as real route inventory.
4. Old canonical screen map retains OTP, wallets and payment-related screens. These are legacy visual designs, **not authorization to implement OTP or payment**. Document the approved functional substitute before activating them.
5. Existing v31 live components should provide data/actions as adapters to original layout components; do not introduce a third visual app.
6. Preserve Google OAuth and production DB schema unchanged; do not merge or deploy production.
