## Implemented and verified
1. **Staging QA concurrency cleanup:** the parallel last-seat script has independent random UUID idempotency keys and uses `Promise.allSettled`. A lost HTTP response, unexpectedly two successful bookings, or a failed assertion can never skip checking either key. `staging-parallel-cleanup.mjs` queries both test Rider sessions for their own QA bookings; cancels every still-pending test booking and checks that exactly one seat is available again. Non-cancellable/confirmed bookings cause a loud failure. Unit tests cover two wins, one committed booking after a lost response, and cleanup failure. This is *not evidence* that true two-user concurrent requests have been run.
2. **Staging read-only preflight:** refuses non-Staging host, checks anonymous direct `price_egp` and `price_snapshot_egp` reads are denied, verifies public published-only seat price, and checks internal/owner-only RPC denial. RPCs deliberately hidden from the guest schema may return PostgREST `PGRST202` as a valid denial.
3. **App-role least privilege:** migration `20261120232000_v31_revoke_client_trigger_references.sql` removes `REFERENCES` and `TRIGGER` from `anon` and `authenticated` across 16 public tables. Staging SQL verification found zero such grants after the migration; booking RPC and public seat projection remain functional; original booking records remain unchanged.
4. **Notification ownership and integrity:** migration `20261120234000_v31_notification_ack_privileges.sql` revokes direct notification insert/update/delete for both browser roles and anonymous SELECT; grants authenticated UPDATE only on `read_at`. DB trigger sets the first acknowledgment timestamp from the server clock and preserves it on later updates. Existing recipient RLS remains enforced.
5. **Captain notification UX:** full-capacity and reopened-seat alerts link straight to the existing `My trips` route screen, without introducing a new navigation menu or auto-scheduling.
6. **Staging verification:** checked privilege flags (message and kind UPDATE denied; read_at UPDATE granted; anon notification SELECT denied). In a rollback-only SQL test, a forged 2001 timestamp was replaced with server time and a subsequent attempt to change it to 2099 was ignored. No stored notification was altered. Added contract tests for those rules.

## Limitations / acceptance still outstanding
- The hosted SQL tool did not provide demonstrably independent, simultaneous Postgres sessions for last-seat contention. The first attempted parallel SQL probe produced `CONCURRENCY_TEST_NO_LOCK_CONTENTION`. Do not claim true cross-user concurrency passed.
- The secure QA harness requires an explicitly named `STAGING CONCURRENCY QA` route with exactly one seat free, plus two distinct authorized Google Rider JWTs and one authorized Captain JWT. Tokens must only be passed via safe environment, never logged.
- CI must pass on the **final** PR HEAD, and Cloudflare Staging deployment must match that SHA. Do not cite results from cancelled intermediate runs as final.
- The operational-trip versus recurring-service definition, departure date invalidation and cancellation threshold decisions remain open and must not be inferred.
