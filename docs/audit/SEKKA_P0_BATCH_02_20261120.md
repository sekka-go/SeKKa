# seKKa — P0 batch 02: Captain/Rider pricing boundary and CI segregation
Date: 20 November 2026. Work in PR #185 only; no Production DB, merge, OAuth, OTP or payments changes.

## Confirmed privacy defect in Staging (read-only evidence)
- `v31_routes` RLS exposed every **published** row to both `anon` and `authenticated`, including private whole-vehicle `price_egp`. Row-level security alone cannot conceal one column.
- `v31_reserve_seats_with_stops` wrote the **whole-vehicle** `v_route.price_egp` into `v31_bookings.price_snapshot_egp`. Read-only aggregate check found one historic Staging booking snapshot equal to its vehicle total.
- Both conflict with the owner's requirement that the Captain's whole-vehicle price never be returned to a passenger.

## Changes in this batch
1. Dedicated `v31_public_route_offers` published-only view returning **indicative seat price** as `ceil(total / approved capacity)` and no private total. Its elevated view rights are constrained by an explicit `where status='published'`, a small fixed allowlist, and controlled grants. This is a secure projection, NOT a general-purpose view over all routes.
2. Revoke direct table-level `SELECT` on `v31_routes` for anon/authenticated; grant only safe column-level `SELECT` while retaining existing RLS restrictions. No authenticated Rider can directly select `price_egp`. Captain route lists and draft readbacks obtain private totals only via `v31_captain_private_prices` (`auth.uid()=captain_id`).
3. Revoke direct `price_snapshot_egp` SELECT for anon/authenticated; preserve historical database records unchanged. Show Rider-owned per-seat **estimate** through `v31_rider_booking_estimate`, never the raw whole-vehicle snapshot. This estimate is not a final invoice or payment state.
4. Rider live route search, nearby results and booking detail use the safe view/estimate. Remove the UI's promise of a 100 EGP security deposit: deposits/payments remain deferred.
5. Separate synthetic Google/Captain E2E specs from ordinary CI; run them only after building the explicitly fake-auth frontend, never against real Staging.
6. Show Captain price guidance using the PRD Haversine×1.35 fallback and configurable 7–12 EGP/km defaults, **labeled as indicative**, not a verified OSRM drive distance or an enforceable final price.

## Staging read-only verification performed after migration
- `has_column_privilege('anon', v31_routes.price_egp, SELECT)=false`
- `has_column_privilege('authenticated', v31_routes.price_egp, SELECT)=false`
- `has_column_privilege('authenticated', v31_bookings.price_snapshot_egp, SELECT)=false`
- Public seat price view readable by `anon`.
- `v31_captain_private_prices` denied to `anon` and executable by `authenticated` (row visibility limited to `auth.uid()`).
- A full signed-in Rider/Captain Staging acceptance test is still required.

## Important remaining P0: DO NOT CLAIM FINISHED
- The old booking RPC still stores a legacy whole-vehicle snapshot for **new** bookings internally. The raw column is now permission-denied to clients, but the **immutable exact seat-price allocation** is not yet in place. Do not treat the estimate as a final or recorded passenger price. Next migration requires deterministic seat indices, handling cancellation/replacement, and snapshot consistency without repricing accepted bookings.
- Historical snapshots are left untouched; any future correction needs an approved append-only audit and customer communication strategy.
- `v31_public_route_offers` publishes seat-level guidance only. Final price/road-distance rules need OSRM or an authorized distance fallback plus configurable server-side pricing settings. No guessed road distance was enforced.
- Lifecycle split between recurring line and dated operational trip remains an open owner decision. No auto departure date or payment was introduced.
