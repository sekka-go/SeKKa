# Handoff — Phase 11 Commute Pool backend

## Implemented

- Added independent migration `010_pool_domain.sql` for groups, riders, subscriptions, scheduled outbound/return trips, ordered stops, gross ledger entries, cancellation records, notification inbox, and captain availability statistics. Existing legacy trip/matching migrations are unchanged.
- Added authenticated rider APIs for group creation/join, pre-formed group confirmations, seat completion, price approval, service-day/package cancellation, and notifications.
- Added captain APIs for pre-formed groups, adjustable nearby offers, first-accept assignment, route reordering, stop arrival, completion, and one-day absence replacement.
- Captains declare AC status and Faster/Saver tiers; matching offers must fit both the vehicle capability and the captain's selected search radius.
- Weekly/monthly captain assignment applies to the package's service dates. A replacement captain can accept only an absent date. Candidate routes are checked against assigned trips, including estimated deadhead travel.
- If a route has no nearby captain by its scheduled departure, both legs for that service date are cancelled and the date charge is removed/refunded; remaining package dates continue.
- Pricing stores a group fare snapshot from OSRM road distance and duration using the approved four category rows. Outbound and reverse return legs are routed separately; completed legs record gross rider ledger entries.
- Added 72-hour wait notifications to the inbox, generated by the server timer. APIs and assumptions are described in `docs/pool-phase-11-api.md`.
- `/api/health` now identifies phase 11.

## Product rules implemented

- Faster: 3 seats, minimum 2 riders. Saver: 4 seats, minimum 3 riders. Riders can also reserve all remaining seats to run as a whole-car booking.
- Riders select service dates. Daily uses 1 date, weekly 5 dates in one Sunday–Thursday week, monthly 22 dates in one calendar month. All selected days must be Sunday–Thursday.
- Pickup order defaults to join order; outbound drop-offs follow pickup order; return reverses the complete sequence and swaps pickup/drop-off roles.
- Joining points must be within 3 km of the current route line. Captain search defaults to 4 km, can be increased to 10 km, and does not expose empty-drive distance in offers.
- A price increase over 15% pauses route progress for rider approval. Declining removes that rider without a cancellation fee; if the minimum no longer holds, the route is cancelled and the amount due is recorded as refundable.
- Cancellation inside 12 hours charges that service day. Full package cancellation returns unused service days less 10%.
- Daily package cancellation follows the 12-hour service-day rule; weekly/monthly full-package cancellation applies the 10% administration fee to the unused-day refund.

## Integration boundaries

- Routing uses an OSRM-compatible service with local `http://127.0.0.1:5000` as the default and `SEKKA_ROUTING_URL` as the override. No map tiles or UI are part of this backend phase. Riders' coordinates are not sent to a public routing service by default.
- Payment gateway, refund execution, and commission allocation are deferred. Fare/refund values are quotes and accounting calculations only; offers are not gated on payment state. No Grok integration was added because core matching and price rules are deterministic.
- Notifications persist in the database and are exposed by a polling API. No push/SMS adapter is configured.
