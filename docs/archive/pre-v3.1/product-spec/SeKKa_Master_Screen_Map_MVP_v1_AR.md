# SeKKa — Master Screen Map

- **الإصدار:** 1.0 — MVP
- **المنصة:** PWA قابلة للتثبيت من رابط
- **اللغة:** العربية — RTL
- **الأدوار:** زائر، راكب، كابتن، إدارة
- **الحالة المالية:** عمولة المنصة 0%، والدفع مباشرة بين الراكب والكابتن.

> مهم: دي خريطة المنتج المطلوبة، مش تأكيد إن كل الشاشات دي موجودة بالفعل في المشروع الحالي. قبل التنفيذ، لازم Codex يراجع المشروع ويحدد الموجود والناقص.

## 2. الشاشات العامة وتسجيل الدخول

### A-01 — شاشة البداية Splash

**الهدف:** عرض هوية سِكّة أثناء تحميل التطبيق والتحقق من الجلسة.

تحتوي على:

- شعار سِكّة.
- اسم التطبيق.
- مؤشر تحميل بسيط عند الحاجة.

التنقل:

- المستخدم المسجل دخوله ← الصفحة الرئيسية المناسبة لدوره.
- المستخدم غير المسجل ← الصفحة الرئيسية العامة أو تسجيل الدخول.
- المستخدم الذي يحتاج إلى استكمال بياناته ← شاشة استكمال البيانات المناسبة.

### A-02 — الصفحة الرئيسية العامة

تحتوي على:

- الشعار.
- تعريف مختصر بخدمة سِكّة.
- زر «ابدأ رحلتك».
- زر تسجيل الدخول.
- زر إنشاء حساب.
- شرح مبسط لطريقة العمل.
- فئات المركبات.
- روابط الشروط والخصوصية.
- وسيلة التواصل مع الدعم.

لا تظهر وظائف الإدارة كزر عام للمستخدمين.

### A-03 — تسجيل الدخول

تحتوي على:

- حقول بيانات الدخول وفق وسيلة المصادقة المعتمدة.
- زر تسجيل الدخول.
- رابط استعادة الحساب.
- رابط إنشاء حساب.
- رسائل الخطأ وحالة التحميل.

**قرار مفتوح:** طريقة تسجيل الدخول والتحقق من الحساب لم تُحسم نهائيًا، ويجب فصلها تمامًا عن كود الدفع.

### A-04 — إنشاء حساب

تحتوي على:

- البيانات الأساسية المطلوبة.
- بيانات التواصل المطلوبة.
- الموافقة على الشروط والخصوصية.
- زر إنشاء الحساب.
- رسائل نجاح أو خطأ.

بعد إنشاء الحساب، يُوجّه المستخدم إلى استكمال أي بيانات إلزامية ناقصة.

### A-05 — استعادة الحساب

تحتوي على:

- البيانات المطلوبة لاستعادة الوصول.
- تعليمات الاستعادة.
- نتيجة العملية.
- خيار العودة إلى تسجيل الدخول.

### A-06 وA-07 — الشروط والخصوصية

صفحتان لعرض النصوص القانونية المعتمدة.

يجب أن تتضمن الشروط توضيحًا مناسبًا لطبيعة الدفع المباشر بين الراكب والكابتن، وحدود مسؤولية المنصة، وسياسات الإلغاء والنزاعات بعد اعتمادها.

## 3. تجربة الراكب Passenger

### B-01 — الصفحة الرئيسية للراكب

دي أهم شاشة للراكب بعد تسجيل الدخول.

تحتوي على:

- ترحيب مختصر.
- بطاقة الاشتراك الحالي، إن وجد.
- حالة المجموعة الحالية.
- حالة التجديد إذا كان مفتوحًا.
- زر «ابحث عن رحلة».
- زر «أنشئ طلب تنقل».
- أحدث الإشعارات.
- اختصار إلى الاشتراكات.
- اختصار إلى الملف الشخصي.

**حالات الشاشة**

- راكب جديد لا يملك اشتراكًا.
- راكب لديه طلب مطابقة مفتوح.
- راكب ينتظر اكتمال المجموعة.
- راكب لديه اشتراك نشط.
- راكب يحتاج إلى تجديد الاشتراك.
- راكب لديه طلب دفع غير مكتمل.
- راكب يجري البحث له عن بديل.

تتغير البطاقات والإجراءات حسب حالة المستخدم، ولا تظهر إجراءات غير متاحة لحالته.

### B-02 — البحث عن رحلة

تحتوي على:

- نقطة الانطلاق.
- نقطة الوصول.
- أيام التنقل.
- وقت الذهاب.
- وقت العودة.
- فئة المركبة المفضلة.
- خيارات المرونة المعتمدة.
- زر البحث.

يجب توضيح الحقول الإلزامية، وعدم فرض نقطة تجمع بديلة دون موافقة الراكب عند الحاجة.

### B-03 — إنشاء طلب تنقل

تُستخدم عندما لا يجد الراكب عرضًا مناسبًا أو يريد تسجيل احتياجه للمطابقة.

تحتوي على:

- بيانات المسار.
- الجدول الأسبوعي.
- الأوقات.
- الفئة المفضلة.
- نقاط التجمع المقبولة.
- ملخص الطلب.
- زر إرسال الطلب.

بعد الإرسال، تظهر حالة الطلب وما إذا كان يبحث عن تطابق.

### B-04 — نتائج المطابقة

تعرض العروض المتوافقة في صورة بطاقات.

كل بطاقة تعرض:

- اسم أو وصف الكابتن وفق سياسة العرض.
- فئة المركبة.
- السعر الشهري.
- ملخص المسار.
- أيام التشغيل.
- أوقات الذهاب والعودة.
- المقاعد المتاحة.
- نقاط التجمع ذات الصلة.
- حالة العرض.
- زر «عرض التفاصيل».

تتضمن الشاشة:

- الفلاتر.
- ترتيب النتائج.
- حالة عدم وجود نتائج.
- خيار تعديل معايير البحث.

### B-05 — تفاصيل العرض

تعرض المعلومات اللازمة لاتخاذ القرار:

- تفاصيل المسار.
- جدول التشغيل.
- فئة المركبة.
- السعة المتاحة.
- السعر.
- نقاط التجمع والنزول.
- بيانات الكابتن المسموح بعرضها.
- حالة اعتماد الكابتن.
- شروط الاشتراك المعتمدة.
- زر «طلب الانضمام».

### B-06 — طلب الانضمام والحجز

تعرض:

- ملخص العرض.
- السعر.
- دورة الاشتراك.
- بيانات الرحلة.
- الشروط المطلوبة.
- تأكيد رغبة الراكب في الانضمام.

بعد التأكيد، ينشأ طلب الحجز وفق قواعد المطابقة والسعة.

لا يعني إنشاء طلب الانضمام أن الاشتراك أصبح نشطًا.

### B-07 — تفاصيل المجموعة

تعرض:

- حالة المجموعة.
- المسار.
- الجدول.
- فئة المركبة.
- حالة اكتمال العدد.
- المقاعد المتاحة.
- حالة تأكيد المجموعة.
- الاشتراك المرتبط بالراكب.
- الإجراءات المتاحة وفق الحالة.

لا تعرض معلومات الركاب الآخرين إلا بالقدر المسموح به.

### B-08 — اشتراكاتي

قائمة تشمل:

- الاشتراكات الحالية.
- الاشتراكات السابقة.
- الاشتراكات التي تنتظر التفعيل.
- الاشتراكات التي تحتاج إلى دفع أو إجراء.
- الاشتراكات التي تنتظر التجديد.

لكل اشتراك:

- الحالة.
- السعر.
- فترة الاشتراك.
- المجموعة.
- الإجراء التالي المطلوب.

### B-09 — تفاصيل الاشتراك

تعرض:

- بيانات الاشتراك.
- حالة التفعيل.
- الكابتن.
- المجموعة.
- المسار.
- الجدول.
- المبلغ.
- وسيلة الدفع.
- سجل الأحداث المهم.
- حالة التجديد.
- رابط إيصال سِكّة.

### B-10 — إيصال سِكّة

تعرض:

- رقم مرجع الإيصال.
- تفاصيل الاشتراك.
- المبلغ المطلوب.
- فترة الاشتراك.
- المسار والجدول.
- بيانات الدفع اللازمة.
- حالة الدفع.

يجب أن تحتوي على توضيح واضح:

**«هذا إيصال بتفاصيل الاشتراك، وليس إثباتًا على استلام المبلغ.»**

### B-11 — اختيار وسيلة الدفع

الخيارات المتاحة حسب العرض:

- كاش.
- محفظة إلكترونية.
- InstaPay.

تعرض الشاشة:

- المبلغ.
- بيانات المستلم اللازمة.
- تعليمات الدفع.
- الإيصال.
- زر بدء إجراء الدفع.

عند الضغط، ينشأ طلب دفع مرتبط بالاشتراك، ويصل إشعار للكابتن.

### B-12 — رفع إثبات التحويل

تظهر عند اختيار الدفع الإلكتروني.

تحتوي على:

- المبلغ المطلوب.
- وسيلة الدفع.
- رفع صورة أو ملف الإثبات.
- معاينة الملف.
- زر إرسال الإثبات.
- حالة الإرسال.

بعد رفع الإثبات، تظهر رسالة تفيد بأن الكابتن يحتاج إلى مراجعة التحويل والتأكد من وصول المبلغ.

### B-13 — انتظار تأكيد الكابتن

تعرض:

- المبلغ.
- وسيلة الدفع.
- حالة الطلب.
- حالة إثبات التحويل إن وجد.
- وقت بدء الطلب.
- تعليمات الانتظار.
- خيار التواصل أو تقديم بلاغ عند الحاجة.

لا تعرض هذه الشاشة أن الدفع اكتمل قبل تأكيد الكابتن الاستلام فعليًا.

### B-14 — تأكيد كود الدفع

بعد أن يؤكد الكابتن استلام المبلغ ويطلب إنشاء الكود، يظهر الكود مباشرة في واجهة الراكب.

تعرض الشاشة:

- كود الدفع.
- بيانات الاشتراك المرتبط به.
- تعليمات تأكيد الكود.
- زر «تأكيد كود الدفع».
- رسالة خطأ عند فشل التحقق.
- حالة انتهاء الصلاحية إذا كانت القاعدة معتمدة.

الكود ليس رمز تسجيل الدخول، ولا يجب مطالبة الراكب بإعادة كتابته يدويًا إذا كان تصميم التدفق المعتمد يسمح بظهوره مباشرة.

### B-15 — نتيجة الدفع وتفعيل الاشتراك

تعرض إحدى الحالات:

- تم التحقق من كود الدفع.
- تم تفعيل الاشتراك.
- ما زال التفعيل في انتظار إجراء آخر.
- فشل التحقق.
- انتهت صلاحية الكود.
- يوجد نزاع أو مشكلة تحتاج إلى مراجعة.

يجب أن تكون رسالة النجاح مرتبطة بنتيجة حقيقية من الخادم.

### B-16 — التجديد الشهري

تعرض:

- الاشتراك الذي يحتاج إلى التجديد.
- قرار الكابتن بشأن الاستمرار.
- السعر والشروط للدورة الجديدة.
- المهلة المتبقية.
- زر الموافقة على التجديد.
- زر عدم التجديد.

لا يجوز اعتبار عدم الرد موافقة تلقائية.

### B-17 — البحث عن كابتن بديل

تظهر عند تعذر استمرار الكابتن الأصلي أو انتقال المجموعة إلى حالة البحث عن بديل.

تعرض:

- سبب البحث.
- حالة الطلب.
- تفاصيل الجدول والمسار.
- البدائل المقترحة عند وجودها.
- تفاصيل البديل.
- طلب موافقة الراكب عند الحاجة.

لا تعرض بديلًا باعتباره مؤكدًا قبل تأكيده فعليًا.

### B-18 وB-19 — المحادثات

قائمة المحادثات تعرض المجموعات أو المحادثات التي يحق للراكب الوصول إليها.

تفاصيل المحادثة تعرض الرسائل المرتبطة بالمجموعة، مع:

- إرسال الرسائل.
- حالة الإرسال.
- بيانات المرسل.
- خيار الإبلاغ عن إساءة استخدام.

### B-20 — الإشعارات

تعرض الإشعارات المتعلقة بـ:

- المطابقة.
- الحجز.
- المجموعة.
- الدفع.
- الاشتراك.
- التجديد.
- الكابتن البديل.
- الشكاوى.
- التقييمات.

### B-21 — التقييمات

تتيح للراكب تقييم الكابتن أو الخدمة في الفترة المسموح بها، وفق سياسة التقييم المعتمدة.

### B-22 وB-23 — الشكاوى والبلاغات

- **تقديم شكوى:** اختيار النوع، وكتابة التفاصيل، وإرفاق الأدلة عند الحاجة.
- **متابعة الشكوى:** عرض الحالة والتحديثات والقرار النهائي عند صدوره.

### B-24 — الملف الشخصي والإعدادات

تحتوي على:

- بيانات الحساب.
- بيانات التواصل.
- تعديل البيانات المسموح بها.
- إعدادات الإشعارات.
- الخصوصية.
- المساعدة.
- الشروط والأحكام.
- تسجيل الخروج.

## 4. تجربة الكابتن Captain

### C-01 — الصفحة الرئيسية للكابتن

تعرض ملخصًا تشغيليًا:

- حالة اعتماد الحساب.
- العروض المنشورة.
- المجموعات الحالية.
- طلبات الركاب.
- الاشتراكات التي تحتاج إلى إجراء.
- طلبات الدفع المنتظرة.
- طلبات التجديد.
- التنبيهات المهمة.

يجب إبراز الإجراءات ذات الأولوية، مثل طلب دفع ينتظر تأكيد الاستلام.

### C-02 — حالة اعتماد الحساب

تعرض:

- حالة المراجعة.
- الوثائق المطلوبة.
- الوثائق المقبولة أو المرفوضة.
- سبب الرفض عند وجوده.
- الخطوة التالية.

لا يُسمح بنشر عرض قبل استيفاء شروط الاعتماد.

### C-03 — استكمال الملف والوثائق

تتيح:

- إدخال البيانات المطلوبة.
- رفع الوثائق.
- معاينة الملفات.
- إعادة رفع المستندات المطلوبة.
- إرسال الملف للمراجعة.

### C-04 — بيانات المركبة

تعرض:

- بيانات المركبة.
- فئتها.
- السعة المعتمدة.
- الوثائق المطلوبة.
- حالة الاعتماد.

يجب ألا تتجاوز السعة المستخدمة في العروض السعة المعتمدة.

### C-05 — عروض التنقل

تعرض:

- العروض النشطة.
- العروض غير المنشورة.
- العروض المتوقفة.
- العروض المكتملة أو المنتهية.
- حالة كل عرض.

### C-06 — إنشاء عرض جديد

تحتوي على:

- نقطة البداية.
- نقطة النهاية.
- المسار.
- نقاط التجمع والنزول.
- أيام التشغيل.
- أوقات الذهاب والعودة.
- فئة المركبة.
- السعة.
- السعر الشهري.
- بيانات وسيلة الدفع المتاحة.
- مراجعة نهائية قبل النشر.

### C-07 — تعديل العرض

تسمح بتعديل البيانات المسموح بها وفق حالة العرض.

إذا كان التعديل يؤثر على مجموعة أو اشتراك مؤكد، يجب أن يطبق النظام قواعد التغيير والموافقة المعتمدة.

### C-08 وC-09 — طلبات الركاب

قائمة الطلبات تعرض طلبات الانضمام المرتبطة بالعروض.

تفاصيل الطلب تعرض:

- بيانات الطلب ذات الصلة.
- توافق المسار والجدول.
- الحالة.
- الإجراءات المتاحة.

يجب ألا يستطيع الكابتن تجاوز قواعد المطابقة أو السعة.

### C-10 — إدارة المجموعات

تعرض جميع مجموعات الكابتن وحالاتها:

- قيد التجميع.
- جاهزة للتأكيد.
- مؤكدة.
- نشطة.
- في انتظار التجديد.
- تبحث عن بديل.
- مكتملة أو ملغاة.

### C-11 — تفاصيل المجموعة

تعرض:

- المسار والجدول.
- حالة المجموعة.
- عدد المقاعد.
- قائمة الاشتراكات.
- حالة كل اشتراك.
- إجراءات التشغيل المسموح بها.
- سجل الأحداث الأساسي.

### C-12 — قائمة الركاب

تعرض الركاب المرتبطين بالمجموعة، مع الاقتصار على البيانات اللازمة للتشغيل.

### C-13 — اشتراكات المجموعة

تعرض:

- اسم الراكب أو معرفه المناسب.
- فترة الاشتراك.
- المبلغ.
- وسيلة الدفع.
- حالة طلب الدفع.
- حالة التفعيل.
- الإجراءات المطلوبة من الكابتن.

### C-14 — طلبات الدفع

قائمة بطلبات الدفع التي تحتاج إلى إجراء.

تتضمن:

- الاشتراك المرتبط.
- الراكب.
- المبلغ.
- وسيلة الدفع.
- وجود إثبات تحويل.
- حالة الدفع.
- الإجراء التالي.

### C-15 — تفاصيل طلب الدفع

تعرض:

- إيصال سِكّة.
- بيانات الاشتراك.
- وسيلة الدفع.
- المبلغ المطلوب.
- إثبات التحويل إن وجد.
- تاريخ إنشاء الطلب.
- سجل الحالات.

يجب الفصل بين إنشاء الإيصال وإثبات التحويل وتأكيد الاستلام.

### C-16 — تأكيد استلام المبلغ

تعرض رسالة تأكيد صريحة، مثل:

**«هل تؤكد أنك استلمت مبلغ الاشتراك كاملًا بالفعل؟»**

مع:

- تفاصيل العملية.
- المبلغ.
- زر تأكيد الاستلام.
- زر الرجوع.

يجب ألا يسمح النظام بتأكيد الاستلام لطلب دفع لا يخص الكابتن.

### C-17 — إرسال كود الدفع

بعد تأكيد الاستلام، يظهر زر:

**«إرسال كود الدفع»**

عند الضغط:

1. يتحقق الخادم من صلاحية العملية.
2. ينشئ كودًا مرتبطًا بطلب الدفع.
3. يسجل وقت الإنشاء.
4. يجعل الكود متاحًا للراكب مباشرة.
5. يحدث حالة العملية.

لا يجوز إنشاء الكود قبل تأكيد استلام المبلغ.

### C-18 — متابعة حالة الدفع

تعرض:

- انتظار تأكيد الراكب.
- نجاح التحقق.
- انتهاء صلاحية الكود.
- فشل التحقق.
- حالات النزاع.

### C-19 — التجديد الشهري

تعرض:

- المجموعات التي اقترب تجديدها.
- المهلة المتبقية للرد.
- تفاصيل الدورة القادمة.
- زر تأكيد الاستمرار.
- الإجراءات البديلة المسموح بها.

### C-20 — طلب البحث عن بديل

تتيح للكابتن تسجيل تعذر الاستمرار وفق السياسة المعتمدة، مع توضيح:

- سبب الطلب.
- الدورة المتأثرة.
- المجموعات المتأثرة.
- الحالة الحالية للطلب.

### C-21 وC-22 — المحادثات والإشعارات

تتيح متابعة المحادثات المرتبطة بالمجموعات، والإشعارات التشغيلية وطلبات الدفع والتجديد.

### C-23 — التقييمات والبلاغات

تعرض التقييمات والبلاغات ذات الصلة بالكابتن، مع إجراءات الرد أو الاعتراض المسموح بها.

### C-24 — الملف الشخصي والإعدادات

تشمل البيانات الشخصية، وبيانات التواصل، وإعدادات الإشعارات، وإدارة الحساب.

## 5. لوحة الإدارة Admin

لوحة الإدارة لازم تكون منفصلة وظيفيًا عن تجربة الراكب والكابتن، وتخضع لصلاحيات إدارية حقيقية على الخادم.

### D-01 — تسجيل دخول الإدارة

- تسجيل الدخول.
- التحقق من صلاحية الدور الإداري.
- رفض وصول المستخدم العادي.
- تسجيل الأحداث الأمنية اللازمة.

لا يلزم وضع زر دخول الإدارة على الصفحة العامة؛ يمكن توفير مسار دخول منفصل وفق التصميم الأمني المعتمد.

### D-02 — لوحة المؤشرات الرئيسية

تعرض مؤشرات تشغيلية، مثل:

- عدد المستخدمين.
- عدد الكباتن المعتمدين.
- عدد الكباتن المنتظرين للمراجعة.
- العروض النشطة.
- المجموعات قيد التجميع.
- المجموعات المؤكدة.
- الاشتراكات النشطة.
- طلبات الدفع المنتظرة.
- النزاعات المفتوحة.
- الشكاوى التي تحتاج إلى إجراء.

الأرقام المعروضة يجب أن تأتي من بيانات حقيقية، لا من قيم تجريبية.

### D-03 وD-04 — إدارة المستخدمين

- **قائمة المستخدمين:** بحث وفلاتر حسب الدور والحالة.
- **تفاصيل المستخدم:** بيانات الحساب المسموح بها، وسجل الإجراءات ذات الصلة، وحالة الحساب، والإجراءات الإدارية المتاحة.

### D-05 وD-06 — إدارة الكباتن ومراجعة الوثائق

تتضمن:

- قائمة طلبات الاعتماد.
- تفاصيل الكابتن.
- مراجعة الوثائق.
- قبول أو رفض الطلب.
- تسجيل سبب القرار.
- سجل المراجعة.

### D-07 — إدارة المركبات

تتيح مراجعة بيانات المركبات ووثائقها وفئاتها وسعتها وحالتها.

### D-08 وD-09 — إدارة العروض وطلبات الركاب

تتيح مراجعة العروض والطلبات وحالاتها، مع إمكان إيقاف عرض أو اتخاذ إجراء إداري وفق الصلاحيات المعتمدة.

### D-10 وD-11 — إدارة المجموعات

تتيح:

- البحث عن مجموعة.
- مراجعة المقاعد والسعة.
- الاطلاع على حالة الاشتراكات.
- متابعة المجموعات المتعثرة.
- مراجعة حالات البحث عن بديل.
- عرض سجل الأحداث.

### D-12 — إدارة الاشتراكات

تعرض:

- الاشتراكات الحالية والسابقة.
- حالة التفعيل.
- فترة الاشتراك.
- حالة التجديد.
- المبلغ.
- طلب الدفع المرتبط.

### D-13 وD-14 — مراقبة عمليات الدفع

تعرض:

- طلبات الدفع.
- وسيلة الدفع.
- إثبات التحويل.
- تأكيد الكابتن.
- حالة كود الدفع.
- نتيجة التحقق.
- حالة الاشتراك.

لا تعني هذه الشاشة أن سِكّة يتحكم في الأموال أو يستطيع تأكيد وصول التحويلات الخارجية آليًا.

### D-15 — إدارة النزاعات المالية

تعرض:

- تفاصيل النزاع.
- الأطراف.
- مرجع الدفع.
- الأدلة.
- سجل الأحداث.
- الحالة.
- القرار الإداري وسببه.

لا يجوز إنشاء قرار مالي أو استرداد أموال خارج صلاحيات المنصة الفعلية.

### D-16 — إدارة الشكاوى والبلاغات

تتيح تصنيف الشكاوى، وتعيين المسؤول عنها، وتسجيل التحديثات والقرار النهائي.

### D-17 — إدارة التقييمات

تتيح مراجعة البلاغات المتعلقة بالتقييمات واتخاذ إجراءات وفق سياسة معتمدة، دون حذف التقييمات اعتباطيًا.

### D-18 — إدارة الإشعارات

تعرض سجلات الإرسال والحالة والأخطاء، وتتيح إدارة قوالب الإشعارات المعتمدة.

### D-19 — إدارة العمولة المستقبلية

تحتوي على:

- النسبة النشطة حاليًا: 0%.
- حقل نسبة مستقبلية مقترحة.
- معاينة التغيير.
- حالة خطة الإشعارات.
- سجل الخطط السابقة.

الإجراء الأساسي: **«ابدأ خطة العمولة الجديدة»**

القواعد:

1. إدخال النسبة وحده لا يغير العمولة النشطة.
2. إدخال النسبة وحده لا يرسل إشعارات.
3. الضغط على الزر وتأكيده يبدأ خطة الإشعارات المعتمدة.
4. الإشعارات لا تعني بدء التحصيل.
5. لا تُفعّل آلية تحصيل مستقبلية قبل اعتماد قواعدها وتنفيذها.

### D-20 — إعدادات التشغيل

يمكن أن تحتوي على الإعدادات التشغيلية التي تقرر الإدارة اعتمادها، بشرط تحديد ما يمكن تغييره وما يحتاج إلى مراجعة تقنية.

لا ينبغي إضافة إعدادات لقرارات لم تُحسم بعد ثم تفعيلها بقيم افتراضية مخترعة.

### D-21 — التقارير والتحليلات

تعرض مؤشرات:

- المطابقة.
- اكتمال المجموعات.
- التجديد.
- الإلغاء.
- الغياب.
- الشكاوى.
- النزاعات.
- أداء العروض.

### D-22 — سجل التدقيق Audit Log

يعرض:

- الفاعل.
- الإجراء.
- الكيان المتأثر.
- الوقت.
- القيم السابقة والجديدة عند الحاجة.
- سبب التغيير.
- نتيجة العملية.

يجب ألا يستطيع المستخدم الإداري العادي تعديل السجل أو حذفه.

### D-23 — إدارة صلاحيات فريق الإدارة

تتيح تحديد الصلاحيات حسب الدور الإداري، بحيث لا يمتلك كل موظف جميع الصلاحيات افتراضيًا.

## 7. شاشات مهمة لازم ما تتنسيش

في أي تطبيق كبير، المشكلة مش بس في نسيان شاشة رئيسية؛ المشكلة في نسيان الحالات البديلة والأخطاء.

عشان كده، لازم كل مجموعة شاشات تدعم الحالات المناسبة لها:

| الحالة | السلوك المطلوب |
|---|---|
| لا توجد نتائج | توضيح السبب وإتاحة تعديل البحث |
| لا توجد مقاعد | منع الحجز وعرض الحالة الصحيحة |
| المجموعة لم تكتمل | عرض الحالة والخطوة التالية |
| الكابتن لم يُعتمد | منع نشر العروض |
| إثبات التحويل غير مرفوع | توضيح الإجراء المطلوب |
| الكابتن لم يؤكد الاستلام | إبقاء الدفع قيد الانتظار |
| كود الدفع غير صحيح | رفض العملية مع رسالة مفهومة |
| كود الدفع منتهي | إظهار الحالة والإجراء المسموح |
| انقطاع الإنترنت | توضيح تعذر الاتصال وعدم الادعاء بنجاح العملية |
| انتهت مهلة التجديد | تطبيق الحالة المعتمدة على الخادم |
| الكابتن انسحب | عرض حالة البحث عن بديل |
| الشكوى مفتوحة | عرض رقمها وحالتها |
| لا توجد إشعارات | عرض حالة فارغة واضحة |
| لا توجد اشتراكات | توجيه الراكب للبحث عن رحلة |

## 8. التنقل الرئيسي المقترح على الهاتف

عشان التطبيق PWA وموجه للاستخدام اليومي على الموبايل، المقترح شريط تنقل سفلي بسيط، يتغير حسب الدور.

### للراكب

1. الرئيسية
2. ابحث
3. اشتراكاتي
4. الإشعارات
5. حسابي

### للكابتن

1. الرئيسية
2. عروضي
3. مجموعاتي
4. الإشعارات
5. حسابي

### للإدارة

الأفضل استخدام لوحة ويب إدارية ذات قائمة جانبية على الشاشات الكبيرة، مع تصميم متجاوب عند فتحها من الهاتف.

دي توصية تصميمية وليست قرارًا نهائيًا بشأن شكل التنقل.

## 9. ترتيب التنفيذ الصحيح

مش لازم نبني كل الشاشات مرة واحدة. الأفضل تنفيذها على مراحل، مع ربط كل شاشة بالوظائف الحقيقية.

| المرحلة | الشاشات الأساسية |
|---|---|
| 1 | البداية، الدخول، إنشاء الحساب، الأدوار، الصفحة الرئيسية |
| 2 | ملف الكابتن، الوثائق، المركبات، إنشاء العروض |
| 3 | البحث، طلبات الركاب، نتائج المطابقة، تفاصيل العرض |
| 4 | الحجز، المجموعات، تفاصيل المجموعة، السعة |
| 5 | الاشتراكات، إيصال سِكّة، طرق الدفع، إثبات التحويل |
| 6 | تأكيد الاستلام، كود الدفع، التحقق والتفعيل |

## ملاحظة ختامية

الخريطة دي تصلح لتكون قسم **Screen Inventory & Navigation Map** داخل الـPRD.

لكن قبل ما نطلب من Codex تنفيذها، لازم نعمل خطوة مهمة: مطابقة الخريطة مع المشروع الموجود فعلًا، ونحدد أمام كل شاشة هل هي:

- موجودة ومكتملة.
- موجودة لكنها تحتاج إلى تعديل.
- موجودة شكليًا فقط.
- غير موجودة.
- متوقفة على قرار لم يُحسم.

بالطريقة دي هنمنع Codex من إعادة بناء أجزاء موجودة، أو إنشاء شاشات كثيرة من غير ربطها بالـBackend، أو اعتبار الأزرار الشكلية وظائف مكتملة.
